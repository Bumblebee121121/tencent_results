# Stage 5：召回 Baseline 计划书（供 Codex 编写代码）

## 0. 当前阶段

``` text
阶段 0：项目与任务定义                     ✅
阶段 1：数据理解与数据预处理               ✅
阶段 2：EDA 与问题发现                     ✅
阶段 3：样本构造、时间切分与评估协议       ✅
阶段 4：特征工程                           ✅
阶段 5：召回 Baseline                      ← 当前
        ├── ItemCF / I2I
        └── Vanilla Two-Tower
```

Stage 5 的目标不是追求最复杂模型，而是建立两个可信的召回基线：

1.  ItemCF / I2I：验证历史行为共现是否可以预测未来点击。
2.  Vanilla Two-Tower：验证纯用户历史 + 广告 ID
    表示学习是否优于简单协同过滤。

后续 Stage 6 的
Action-aware、Time-aware、Side/MM、History-strength-aware 都必须与 Stage
5 在同一协议下比较。

------------------------------------------------------------------------

# 1. Stage 5 核心目标

召回阶段解决的问题：

> 从大量广告中快速找出用户可能点击的一小批候选广告。

评价核心：

$$
Recall@K=
\frac{TopK中包含真实点击广告的样本数量}
{评估样本总数量}
$$

必须同时报告：

-   Recall@10
-   Recall@50
-   Recall@100

并按照：

-   Overall
-   Head
-   Mid
-   Tail
-   Unseen

分别统计。

# 3. Baseline 1：ItemCF / I2I

## 3.1 目的

验证：

> 用户过去交互过的广告，其相似广告是否能够召回未来点击广告。

------------------------------------------------------------------------

## 3.2 输入

使用训练集历史行为：

``` text
seq_item_rid
seq_action_token
seq_timestamp
```

只使用：

``` text
Train split
```

------------------------------------------------------------------------

## 3.3 用户-广告交互矩阵

构造：

$$
R_{ui}
$$

其中：

用户 u 与广告 i 的交互强度由历史行为决定。

点击行为权重大于曝光行为。

例如：

$$
R_{ui}=\sum_k w(action_k)
$$

其中：

$$
w(click)>w(exposure)
$$

具体权重写入配置，不硬编码。

------------------------------------------------------------------------

## 3.4 Item 相似度

计算：

$$
sim(i,j)
$$

推荐使用余弦相似度：

$$
sim(i,j)=
\frac{i\cdot j}{|i||j|}
$$

保存：

``` text
artifacts/stage5/itemcf/
```

包括：

``` text
item_id
neighbor_item_id
similarity
rank
```

------------------------------------------------------------------------

## 3.5 ItemCF 召回流程

对于用户历史：

$$
H_u
$$

执行：

``` text
历史广告
↓
查找相似广告
↓
合并候选
↓
去除历史已交互广告
↓
得到Top-K
```

------------------------------------------------------------------------

## 3.6 ItemCF 实验

至少比较：

### 行为权重

版本1：

``` text
曝光=1
点击=1
```

版本2：

``` text
点击权重大于曝光
```

观察点击反馈是否有效。

### 历史窗口

比较：

``` text
全部历史

最近N次历史
```

# 4. Baseline 2：Vanilla Two-Tower

## 4.1 目的

建立深度召回基准。

验证：

> 用户历史广告序列 + 广告 ID 表示学习，是否超过 ItemCF。

------------------------------------------------------------------------

# 5. Vanilla Two-Tower 输入

## User Tower

只使用：

``` text
历史广告ID序列
```

不加入：

-   action；
-   timestamp；
-   side feature；
-   MM；
-   history strength。

这些属于 Stage 6。

表示：

$$
H_u=(i_1,i_2,...,i_n)
$$

------------------------------------------------------------------------

## Item Tower

只使用：

``` text
广告ID
```

即：

$$
v_i=Embedding(i)
$$

------------------------------------------------------------------------

# 6. 模型结构

## User Tower

最简单实现：

``` text
历史广告Embedding
        ↓
Pooling
        ↓
用户向量
```

例如：

$$
q_u=
\frac1{|H_u|}
\sum_i e_i
$$

不要提前实现：

-   SDM；
-   Transformer；
-   Attention。

------------------------------------------------------------------------

## Item Tower

$$
v_i=Embedding(i)
$$

------------------------------------------------------------------------

## 匹配函数

采用：

$$
score(u,i)=q_u^Tv_i
$$

------------------------------------------------------------------------

# 7. 训练目标

采用对比学习思想。

正样本：

$$
(u,i^+)
$$

负样本：

$$
(u,i^-)
$$

目标：

$$
score(u,i^+)>score(u,i^-)
$$

可以使用：

-   sampled softmax；
-   InfoNCE。

具体实现根据工程情况选择。

------------------------------------------------------------------------

# 8. Negative Sampling

要求：

-   是真实 target；
-   是用户历史交互广告。

Hard Negative 留到 Stage 6。

# 15. 一句话总结

Stage 5 的目标是建立两个基础召回系统：ItemCF
验证历史行为共现信号，Vanilla Two-Tower 验证纯 ID
表示学习能力。通过统一时间切分、候选池和 Recall@K 评估，为后续 EDA
驱动的召回优化提供可信基准。
